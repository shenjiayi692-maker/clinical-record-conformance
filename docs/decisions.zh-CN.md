# 设计决策

[English](decisions.md) · **中文**

[`methodology.md`](./methodology.md) 说明了这个基准**做什么**。这份文档说明**为什么**、**替代方案是什么**、以及**这个选择付出了什么代价**。五条决策比其余的更重要。

## 校验器从不调用模型

用 LLM 做裁判写起来更省事，而且能覆盖那些难以形式化的规则。

它被否掉，是因为裁判编造分数的机制，和生成器编造事实的机制是同一个。与被测系统共享一种失败模式，不只是让基准在边缘上变弱——它直接抹掉了基准探测它唯一存在理由的那件事的能力。所以 [`src/validator.py`](../src/validator.py) 里根本不包含任何模型调用，这也是为什么公布的表格可以从提交的运行日志重新计算出来，不需要 API key，也不需要网络。

**代价：** 只有能被表达为必填、长度、模式、数值、顺序或时间戳检查的规则才可被测试。真正模糊的临床质量在这个基准之外，而且是被**声明**在外，而不是被悄悄近似。

## 规则来源是加载期不变量，不是文档里的一句承诺

这个仓库的核心主张是：它不包含任何医院模板、任何机构规则。这个主张的价值恰好等于它最弱的那一道执行，而 README 里的一句话是最弱的执行方式——它只能存活到某个人赶时间加一条规则为止。

所以当一条规则声明的 `source` 既不是指向公开国家标准的引用、也不是标识科室层为合成的那个字面标记时，schema 加载会**失败**，而不是告警。一条没有诚实来源的规则进不了系统，因为系统根本起不来。

**代价：** 加一条规则之前，必须先决定它从哪来。这份摩擦正是目的本身。

## 重试重新读源文本，而不是修改上一次的答案

常规的修复循环会把模型自己的输出连同校验错误一起还给它，然后要求它修。这被否掉了。

当失败的那条记录还在上下文里时，模型会围绕它已经编造出来的内容做修补。一个恰好满足规则的捏造值会原封不动地活过这次修复，因为循环里没有任何环节去问它从哪来——而修好的记录随后会被记为一次干净的通过。所以每一次尝试都从源口述记录重新构建，唯一被带过去的只有被违反的规则消息列表。

**代价：** 每次尝试都要重新付一遍完整的输入 token。在提交的这次运行里，三条触发重试的记录比 Arm B 多花了 5.1%。

## 循环拒绝重试源文本回答不了的问题

这是结论所依赖的那条决策，也是统一重试循环会搞错的那一条。

一个对每种违规都重试的循环，会对"填满某个必填字段"施加不断升级的压力。当那个事实在源文本里根本不存在时，唯一能释放这份压力的办法就是编一个看起来合理的值。这样的循环不只是没能阻止捏造——它制造了这个基准存在的意义所要测量的那个失败，然后把结果报告为通过。

所以分区判断会在决定之前重新读一遍口述记录。被违反的必填规则永不重试。数值字段的违规只有在那个数字确实出现在源文本里时才重试。解析、长度、模式和顺序失败是模型可修复的，退回去再试一次；当没有任何一项可重试时，循环停下，记录转人工复核，而不是再去采样一次模型。

3 个格式失败挽回 3 个、11 个源文本缺失挽回 0 个，就是这条决策被测量出来的样子。那个零不是局限。它是循环拒绝捏造——而这是它当下唯一正确的行为。

**代价：** 分区判断需要为每一种规则类型回答"源文本能否裁决这件事？"，而目前只有必填规则和数值字段规则有这个答案。一种新的规则类型必须先写出这个答案，才能在 Arm C 里被信任。

## 头条指标改过一次，排名因此反转

这个基准最初只测量合规率。在那个指标下，Arm A——纯散文、无结构、无校验器——以 93.3% 明显胜出，而结论会是那套结构化机制不值得它的成本。

那个结论是指标的假象。Arm A 得分高，是因为它悄悄补全了 manifest 刻意留空的字段，而由于补全的内容在临床上看起来合理，合规检查无法把它们和正确抽取区分开。这正是问题本身的另一种说法：这种失败模式对最可能被用在它身上的那种测量是不可见的。

头条指标于是改成一个联合指标，要求一条记录既通过校验、又不填充任何受 manifest 控制的缺失项。排名反转，差距收窄到两个百分点以内——一个小得多的主张，回答的是一个难得多的问题。

**代价：** 数字更低，而且需要一整段话来解释。`data/manifest.json` 也必须在生成之前写好，而不是在生成之后评判，这把语料规模限制在手工能构造出来的范围内。
