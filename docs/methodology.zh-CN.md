# 方法学

[English](methodology.md) · **中文**

本仓库是一次公开的、全合成数据的临床文书合规流水线复现。它评测的是约束层的行为，不复现任何医院系统，也不声称具备临床有效性。

## 规则来源

schema 分为两个性质不同的层：

- 公开基线引用国家卫生健康委员会的[《病历书写基本规范》](https://www.nhc.gov.cn/yzygj/c100068/201002/766b58f0dd9242d3b62276e5c88d27dc.shtml)（卫医政发〔2010〕11号）。每一条映射过来的规则都注明其适用条款。
- 科室层规则的来源标记为 `illustrative departmental template (synthetic)`。它们的版式、阈值、编码、封闭词表和顺序约束都是虚构的，不转录任何客户资产。

每条规则都必须有 `source`，schema 加载会拒绝缺失或无法识别的来源。这些 schema 是评测子集，不是完整的病历规范。

## 语料与缺失项的 ground truth

语料包含 20 例内科叙述和 20 例急诊病例，各自以两种形态呈现：有序叙述和碎片式口述。每一对急诊样本来自同一个源事实对象，共享同一个 SHA-256 事实指纹。

[`data/manifest.json`](../data/manifest.json) 记录每个案例的输入形态、事实指纹、被刻意抹去的必填字段，以及预期会暴露该缺失的那条规则。一个填充了受控缺失项的输出会被计为**无据填充**，哪怕那个值听起来完全合理。

这项"有据"检查是刻意收窄的。它只对受控缺失项检测无据填充，并不是一个针对每一句生成内容的通用事实一致性评测器。

## 三个 Arm 与失败路由

- Arm A 接收散文式标准，输出自由文本。
- Arm B 接收严格 JSON 模板，只有一次尝试。
- Arm C 的首次结构化尝试与 B 相同，之后再套用一层源感知的校验策略。

Arm C 把必填字段失败和源文本中不存在的数值事实路由到人工复核。只有模型可修复的解析、格式、术语或顺序失败才会作为规则消息反馈退回去，且总尝试次数最多三次。重试是无状态的，不包含上一次生成的记录。

确定性校验器支持 `required`、长度上下界、必需与禁止的模式、数值字段、章节顺序，以及固定的时间戳格式。它的角色是诊断和路由：重新生成可以修复一个模型的失败，但它无法找回一个从未出现在源文本里的事实。

## 指标

- **原始合规率：** 最终输出没有任何校验器违规。
- **必填字段填充率：** 必填章节含有文本。这并不意味着该文本有据或正确。
- **有据记录：** 没有填充任何受 manifest 控制的缺失项。
- **合规且有据：** 该记录通过校验，且没有对受控缺失项的无据填充。

延迟以中位数和观察到的最大值报告，不用 p95。成本和 Arm C 的延迟包含全部尝试。

## 可复现性

提交的 [`results/final_run.jsonl`](../results/final_run.jsonl) 包含一次逻辑运行：60 条记录、180 条 record-arm 路径，以及 3 次额外的 Arm C 尝试。尝试键唯一且连续，每条记录都覆盖 A/B/C，生成配置恒定，时间戳单调。该文件与产生它的那次带时间戳的单次运行逐字节一致；那次运行在一次瞬时限流后被恢复，配置未做任何改动。

完整结果、失败清单、延迟、成本和配对对照分析见 [`results/report.md`](../results/report.md)。
